# CAD framework services

The JavaScript and native WebAssembly execution tiers share the finite adapters in `src/il/cad-bcl.mjs`. These adapters execute inspected netDxf code while supplying specific framework operations that would otherwise require the managed framework. They do not imply complete support for `System.Enum`, `System.String`, or `System.Drawing`.

| Service | Supported operations |
| --- | --- |
| Enum metadata | Non-generic `GetValues(Type)`, `GetNames(Type)`, `GetUnderlyingType(Type)`, `GetName(Type,Object)` and `IsDefined(Type,Object)` |
| Enum conversion | Non-generic `Parse(Type,String[,Boolean])`; `ToObject(Type, integral)` for all eight integer types; `ToObject(Type,Object)` for integral, enum, Boolean and Char inputs |
| Enum values | `ToString()` and `ToString(String)`, formats G/D/X/F, `Format(Type,Object,String)`, `HasFlag`, `Equals`, `CompareTo`, `GetHashCode`; constrained and boxed enum calls |
| Color values | Default value, `FromArgb(Int32)`, RGB, ARGB, and alpha-plus-Color overloads; A/R/G/B, Name, IsEmpty, IsNamedColor, IsKnownColor, ToArgb, ToString, equality and hashing |
| Named colors | White, Black, Red, Green, Blue, Yellow, Cyan, Magenta and Transparent |
| Ordinal strings | Both `CompareOrdinal` overloads; `Compare`, `Equals`, `Contains`, `StartsWith`, `EndsWith` and string `IndexOf` overloads with explicit ordinal comparison |
| Character strings | `Replace(Char,Char)`, `Contains(Char)`, character `IndexOf` and `LastIndexOf`, `IndexOfAny(Char[])` with optional range, and Trim/TrimStart/TrimEnd with a character or character array |
| String construction/editing | `new String(Char,Int32)` and `Remove(Int32[,Int32])`, with range checks and UTF-16 preservation |
| Composite formatting | `String.Format` with optional provider and one to three objects, an object array, or a `ReadOnlySpan<Object>`; escaped braces, alignment, numeric/enum formats, managed `IFormattable` and `ToString` callbacks |
| Current culture | Runtime-scoped invariant `CultureInfo.CurrentCulture` / `CurrentUICulture` and corresponding `Thread.CurrentThread` properties; invariant culture construction/cache lookup, mutable clones, `TextInfo.ListSeparator`, and mutable number-format providers |
| Numeric rounding/conversion | `Math.Round(Double,Int32)`, `Math.Round(Double,MidpointRounding)`, `Math.Round(Double,Int32,MidpointRounding)` for all five midpoint/directed modes; `Convert.ToInt32(Double)` with ties-to-even and overflow checks |
| Integer parsing | String `Parse` and `TryParse` overloads for all eight integer types, optional `NumberStyles` and format provider, decimal/hex/binary, signs, whitespace, groups, decimal point, exponent, parentheses and currency |
| String comparers | Ordinal and OrdinalIgnoreCase singletons; Compare, Equals and GetHashCode for strings; compatible with supported collection comparer services |

Enum values preserve their actual signed or unsigned underlying width, including 64-bit constants above JavaScript's exact Number range. `GetValues` uses unsigned enum ordering, `Parse` validates numeric overflow and follows CLR whitespace rules (including the difference between leading Unicode whitespace and the numeric parser's trailing whitespace), `IsDefined` distinguishes underlying-type mismatches, and `GetName` does not truncate an out-of-range integer into a matching smaller enum constant. Enum formatting reads `isFlagsEnum` from the PE inspector's real `FlagsAttribute` metadata. Older inspection models without this metadata can format named constants and explicit D/X/F values; unnamed general-format values produce a runtime limitation.

Ordinal comparisons operate on UTF-16 code units. `OrdinalIgnoreCase` uses pinned .NET 10 Unicode ordinal casing tables for comparison, equality, search and collection hash keys. BMP characters, supplementary pairs and isolated surrogates preserve the CLR’s width and search-window behavior; the implementation does not depend on JavaScript case conversion. See [Unicode ordinal comparison](ORDINAL-UNICODE.md) for the runtime fingerprint, table generator and native differential coverage. This exact ordinal surface is separate from the bounded printable-ASCII invariant linguistic comparer described in the [compiled CAD service guide](CAD-COMPILER-SERVICES.md). Other culture-sensitive `StringComparison` values remain explicit runtime limitations. Signature admission alone does not imply every comparison mode is supported.

Colors retain ARGB values, the known-color identity, and empty-state identity. Consequently, known `Color.White` differs from an ARGB color with the same channels, as on .NET. Supported collection equality observes this state. Color naming, drawing surfaces, brushes, image codecs, and platform graphics APIs outside the table remain unsupported.

Generated runtimes start with the invariant culture independently of the host browser locale. Culture state belongs to one generated runtime and its single managed thread. Setting an invariant culture clone changes subsequent provider-free numeric `ToString`, null-provider formatting/parsing, composite numeric formatting, typed Console output, and interpolated strings. The setters do not implement thread scheduling, `AsyncLocal` execution-context propagation, other named cultures, or globalization tables. Unsupported named cultures and arbitrary format providers fail explicitly; culture-sensitive string comparisons retain their existing restrictions. `Environment.NewLine` is `\n`, matching the browser/Linux runtime.

Composite formatting validates every brace and item, preserves the distinction between an array supplied as one object and a params array, invokes managed `IFormattable` implementations with the original provider, and retains those callbacks when selecting native-Wasm exports. Object formatting follows `ToString` when the object does not implement `IFormattable`. `ICustomFormatter` and culture-specific formatter implementations remain unsupported. Numeric specifiers retain the finite format contract below.

Integer parsing validates styles before parsing, preserves all 64 bits, and distinguishes format failures from range overflow. `TryParse` clears its output on an ordinary parse failure; invalid styles throw before changing the output. Provider signs/separators, negative-zero handling, hexadecimal/binary two's-complement interpretation, and null argument/style precedence are checked against .NET. Long numeric inputs are syntax-checked before a bounded BigInt conversion; enormous exponents never allocate enormous powers of ten. Floating-point string parsing is supplied by the additional [compiled CAD services](CAD-COMPILER-SERVICES.md); Decimal parsing, span parsing overloads, and arbitrary custom providers remain outside this integer-parsing surface.

Numeric provider formatting is documented separately in [CAD-NUMERIC-FORMATTING.md](CAD-NUMERIC-FORMATTING.md). The [compiled CAD service guide](CAD-COMPILER-SERVICES.md) describes the additional floating-point, temporal, string, collection, I/O and reflection services used by generated netDxf readers and writers.

## Verification

`tests/cad-bcl-fixture.cs` compiles with the actual Roslyn compiler running on .NET WebAssembly. `tests/cad-bcl-integration.mjs --update` records fresh PE inspection and managed results, then compares the six scenarios in three JavaScript modes and two native WebAssembly modes. The checked-in oracle is replayed by `tests/cad-bcl.test.mjs`, which also verifies the C# source hash, rejected overload shapes, unsupported cultures, and ordinal comparison behavior.

The scenarios cover unsigned enum ordering, names, flags, numeric parsing and overflow, exact 64-bit conversion, boxed/constrained dispatch, default and named colors, color equality in a hash set, UTF-16 comparisons, index ranges, argument exceptions, and comparer contracts. These checks supplement the real-netDxf geometry/entity integration tests; they are not a full-library compatibility claim.

Additional verification uses `tests/cad-culture-fixture.cs` and `tests/cad-parse-fixture.cs`. Their integration scripts compile and invoke the real managed-Wasm oracle, then replay **555 culture/composite/rounding/Enum-whitespace outputs** and **9,545 Parse/TryParse comparison cases** in three JavaScript and two native-Wasm modes. The same fixtures were compared with native .NET 10 execution. `cad-culture.test.mjs` also checks runtime-scoped culture identity and Console array-overload behavior; `cad-parse.test.mjs` checks malformed signatures, output preservation, and bounded handling of huge inputs.

Reference contracts: [Enum.IsDefined](https://learn.microsoft.com/en-us/dotnet/api/system.enum.isdefined?view=net-10.0), [Enum.GetValues](https://learn.microsoft.com/en-us/dotnet/api/system.enum.getvalues?view=net-10.0), and [Color.FromArgb](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.color.fromargb?view=net-10.0).

Further contracts: [Math.Round](https://learn.microsoft.com/en-us/dotnet/api/system.math.round?view=net-10.0), [composite formatting](https://learn.microsoft.com/en-us/dotnet/standard/base-types/composite-formatting), [NumberStyles](https://learn.microsoft.com/en-us/dotnet/api/system.globalization.numberstyles?view=net-10.0), and [Int64.TryParse](https://learn.microsoft.com/en-us/dotnet/api/system.int64.tryparse?view=net-10.0).

The culture fixture also compares typed Console numeric output and interpolated strings after changing the current culture: decimal separators and exponent spelling match native .NET, managed Wasm, and both generated backends. The managed host captures output with a writer whose format provider follows `CurrentCulture`.
